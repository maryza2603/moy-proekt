# Публикация демо на GitHub Pages

## Как устроен репозиторий
- Репозиторий: `maryza2603/moy-proekt`. Каждое демо - отдельная папка в корне (`math-tutor/`, `psychologist/`, `interior/` и т.д.) с `index.html` внутри.
- **Сайт GitHub Pages собирается из ветки `gh-pages`, а НЕ из `main`.** Если положить файлы только в `main`, по ссылке будет 404.
- Адрес демо: `https://maryza2603.github.io/moy-proekt/<папка>/`
- Ссылка на код: `https://github.com/maryza2603/moy-proekt/tree/main/<папка>`

## Порядок действий

1. **Рабочая ветка.** Работай в ветке, которую назначила сессия (`claude/...`). Если её прошлый PR уже влит - пересоздай ветку от свежего `main`:
   `git fetch origin main && git checkout -B <ветка> origin/main`
   Не накладывай новые коммиты на уже влитую историю.

2. **Сделай или поправь демо** в папке `<папка>/index.html`. Одна страница, всё встроено (CSS и JS внутри), внешние только Google Fonts и картинки.

3. **Проверь перед публикацией** скриншотами Playwright (Chromium уже установлен, `playwright install` не запускать):
   `NODE_PATH=$(npm root -g) node script.js` - ширина 1280 и 390 px, слушай `pageerror`.
   - В песочнице внешние картинки и шрифты могут не загрузиться - это не ошибка сайта. Для проверки кадра скачай картинку `curl` локально и подставь во временную копию страницы.
   - Плашки поверх фото не выносить отрицательными отступами за блок с `overflow:hidden` - обрежутся. Центрировать: `left:50%;transform:translateX(-50%)`.
   - Горизонтальное фото в вертикальной рамке: подбирай `object-position`, чтобы человек был в кадре.

4. **Коммит и push в рабочую ветку.** Сообщение коммита по-русски, в конце строки атрибуции из системного напоминания сессии. Push: `git push -u origin <ветка>` (после пересоздания ветки - с `-f`).

5. **Влей в `main`:** создай PR (`mcp__github__create_pull_request`, base `main`) и сразу влей его (`mcp__github__merge_pull_request`, method `merge`) - Мария просит публиковать, это её поток работы.

6. **Выложи в `gh-pages`** (именно это публикует сайт):
   ```
   git fetch origin gh-pages
   git worktree add ../ghp origin/gh-pages   # если ../ghp ещё нет
   cd ../ghp && git checkout -B gh-pages origin/gh-pages && git pull origin gh-pages
   cp -r ../moy-proekt/<папка> .
   git add <папка> && git commit -m "..." && git push origin gh-pages
   ```
   Не удаляй и не трогай чужие папки в `gh-pages`.

7. **Дождись, что сайт обновился.** Не используй `sleep 60` - используй цикл с условием:
   `for i in $(seq 1 40); do grep -q '<уникальная строка из правки>' <(curl -s "https://maryza2603.github.io/moy-proekt/<папка>/?$i") && { echo live; break; }; sleep 6; done`
   Сборка занимает 1-3 минуты. Статус видно в Actions: workflow "pages build and deployment".

8. **Ответ Марии:** ссылка на демо, ссылка на код, ссылка на PR в формате `[PR maryza2603/moy-proekt#N](url)`, что проверено и что нет. Напомни обновить страницу с очисткой кэша, если видно старую версию.
